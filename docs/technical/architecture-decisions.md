# 주요 기술 의사결정

| 결정 | 선택 | 이유 |
|---|---|---|
| 대기열 자료구조 | Redis ZSet | `ZRANK` 순번 조회, 멤버 중복 방지, 중간 이탈 처리 |
| 진입·승급 상태 변경 | Lua | 여러 Redis 명령의 check-then-act를 한 번에 실행 |
| 스케줄러 실행 주체 | Redisson `RLock` | 여러 인스턴스 중 한 대만 작업하고 실패한 인스턴스는 즉시 양보 |
| 좌석 선점 | `SET NX` + TTL | 단일 좌석의 조건부 쓰기를 별도 락 없이 원자 처리 |
| 여러 좌석 선점 순서 | 좌석 ID 정렬 | 최대 3석이라 Lua보다 단순하며 엇갈린 순서의 동시 실패를 방지 |
| Redis HA | Sentinel | 샤딩보다 Master 장애 전환이 우선 |
| 정산 | Spring Batch | 재시작·Step 메타데이터·chunk 처리 지원 |
| 메시지 큐 | 미도입 | 대기열이 DB 진입량을 이미 제한하며 측정된 적재 병목이 없음 |
| 커넥션 풀 확대 | 원복 | 10→30 변경 후 TPS가 같고 p95가 악화 |
| Reader 인덱스 | 미도입 | 조회 대상 520행으로 효과가 재현되지 않음 |

공통 기준은 **측정된 문제에 가장 작은 장치를 적용하고, 효과가 없으면 원복한다**는 것이다. Redis를 사용한다는 이유만으로 모든 연산에 분산락을 걸지 않고, 단일 명령은 원자 명령, 복합 상태 변경은 Lua, 인스턴스 실행 조정은 Redisson으로 책임을 나눴다.
