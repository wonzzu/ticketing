# 선착순 쿠폰의 재고 차감과 롤백 보상

## 문제

쿠폰 100장에 요청이 동시에 몰리면 재고 초과와 한 회원의 중복 발급을 함께 막아야 한다. Redis 발급 후 DB 저장이 실패했을 때 재고와 발급자 기록을 원래 상태로 복구하는 문제도 남는다.

## 해결

`coupon-issue.lua`가 다음 작업을 한 번에 수행한다.

```text
발급자 Set 중복 확인
→ 재고 확인
→ 발급자 SADD
→ 재고 DECR
```

Redis와 MySQL은 같은 트랜잭션에 참여하지 않으므로 DB 롤백이 확정되면 `afterCompletion(ROLLED_BACK)`에서 `coupon-restore.lua`를 실행한다. 복구 Lua는 발급자 Set에서 회원이 실제로 제거됐을 때만 재고를 증가시켜 같은 보상이 반복돼도 재고가 중복 복구되지 않게 했다.

DB에는 `(coupon_id, member_id)` UNIQUE를 두어 Redis 유실·우회 경로·코드 회귀에서도 중복 행을 막는다.

## 검증

- 재고 5개에 서로 다른 회원 6명이 동시 요청: 성공 5건, Redis 재고 0, DB 5건
- DB UNIQUE 위반 유도: DB 롤백 후 issued 기록 제거와 재고 복구
- 복구 중복 실행: 재고가 한 번만 증가

## 좌석 선점과의 차이

좌석은 TTL이 최종 안전망이지만 쿠폰 재고에는 TTL이 없다. 복구 실패가 장기 불일치로 이어질 수 있으므로 운영 단계에서는 재처리 큐나 Outbox를 추가 검토해야 한다.
